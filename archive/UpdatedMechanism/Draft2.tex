\title{\vspace{-8pt}A Normalized Program for Verifiable Computation\\[2pt]
\large Research--Neutral, Safety--First Architecture with Byte--Level Auditability}
\author{}
\date{\today}

\begin{document}

\begin{abstract}
\noindent \textbf{Trust through verifiability.} We present a research--neutral, safety--first architecture for verifiable computation. Consequential steps emit typed receipts with deterministic encodings; header--only aggregation produces a proof surface (Merkle root) that auditors can check from bytes. Norms are specified in temporal logic and gated in CI via SMT; control is formulated as distributionally robust optimization (DRO) with level--1 optimality and conservation receipts and level--2 stability certificates admitted from a revocation--checked cache. Privacy is implemented by selective disclosure with payload Merkle commitments that leave the surface root unchanged.
\end{abstract}

\section{Objectives and Scope}
We aim to formalize auditable computational trust without domain assumptions. The objectives are: compositional evidence; determinism by design; mechanized governance; transparent control; and selective disclosure.

\section{Acceptance Coordinates and Unknowns}
Let $Q=\prod_{i=1}^d Q_i$ with preorder $\preceq$. Index axes into max channels $\mathcal{M}$ and sum channels $\mathcal{S}$ and define $(x\curlywedge y)_i=\max(x_i,y_i)$ if $i\in\mathcal{M}$ and $x_i+y_i$ if $i\in\mathcal{S}$. Each $Q_i$ contains an absorber $\top^{(i)}_{\mathrm{unk}}$; adapters $g$ are monotone homomorphisms with $g(\varnothing)=\top_{\mathrm{unk}}$.

\section{Receipts, Proof Surface, and Selective Disclosure}
Receipts have canonical \emph{headers} (schema id, predicate id, verdict, \texttt{prev\_digest}, \texttt{payload\_root}, \texttt{envlock\_digest}, hash suite) and \emph{payloads} committed via a Merkle root. The proof surface is a Merkle root over canonical headers only. Redaction preserves the surface; reveals include per-field inclusion proofs.

\begin{auditbox}
\textbf{Audit Hook.} Any single--byte mutation in a header flips the surface root with overwhelming probability; payload redaction leaves the root unchanged when inclusion proofs verify against the committed \texttt{payload\_root}.
\end{auditbox}

\section{Norms: STL with SMT Gating}
Norms are stated in Signal Temporal Logic (STL) with quantitative semantics; bounded monitors compile to SMT--LIB (QF\_LRA) and gate changes in CI. Dense--time properties are monitored via robust--satisfaction intervals and the lower bound enforced online.

\section{Control as DRO with Receipts}
Control is a distributionally robust program over a Wasserstein ball. Runtime artifacts: (i) level--1 receipts: convex class declaration (QP/SOCP/SDP), KKT residuals and duality gap within tolerances; conservation receipts verifying $\Delta V$ versus declared spend; (ii) level--2 certificates: PR/ISS from audited cache keyed by component digests, with revocation checks before use.

\section{Mechanized Governance (Monotone Safety)}
Let $\mathrm{MF}(N)$ be must--fail IDs in norms bundle $N$. CI enforces $\mathrm{MF}(N_t)\subseteq \mathrm{MF}(N_{t+1})$. Optionally, entailment between STL revisions is proved by SMT. Batches are summarized by epoch receipts committing prior headers so archival does not break verification.

\section{Rails and Clamp States}
Rails define banded operating regions (Green/Amber/Red) with hysteresis and dwell; transitions are driven by guard margins and certificate status. Policies emit selective--disclosure receipts and can gate pipeline modes.

\section{Core Lemmas (Short Proofs)}
\begin{proposition}[Header Tamper Detectability]
If $H$ is collision--resistant and the surface root is a Merkle root over canonical headers, any header byte mutation changes the root with overwhelming probability.
\end{proposition}
\begin{proof}
A changed header yields a different leaf hash; Merkle recomputation propagates to the root unless a collision occurs in $H$.
\end{proof}

\begin{lemma}[Redaction Invariance]
If a header commits to payload root $\rho$, selective disclosure that preserves $\rho$ leaves the surface root unchanged.
\end{lemma}
\begin{proof}
The surface aggregates headers only; inclusion proofs check reveals against $\rho$.
\end{proof}

\begin{proposition}[Distributivity of $*$ over $\sqcup$ for Chains]
Let $A,B$ be sets of valid chains; let $c$ be a valid chain. Then $c*(A\sqcup B)=(c*A)\sqcup(c*B)$.
\end{proposition}
\begin{proof}
Prefixing by $c$ maps each chain to a longer chain; it distributes over set union pointwise. The surface commitment is order--insensitive due to sorting canonical headers.
\end{proof}

\begin{proposition}[Monotone Safety of Obligations]
If CI enforces $\mathrm{MF}(N_t)\subseteq \mathrm{MF}(N_{t+1})$ for all $t$, safety obligations are monotone nondecreasing across versions.
\end{proposition}
\begin{proof}
Set inclusion prevents removal of any previously required must--fail; additions tighten obligations; equality preserves them.
\end{proof}

\section{Verification Obligations (VOs)}
\begin{itemize}
  \item \textbf{VO-ROOT-EQUAL:} Replays on identical inputs yield identical surface roots across platforms.
  \item \textbf{VO-LEDGER-TAMPER:} Single--byte header mutations alter the root.
  \item \textbf{VO-SD-CORRECT:} Selective--disclosure proofs verify against \texttt{payload\_root}; root unchanged.
  \item \textbf{VO-NB-MONO:} $\mathrm{MF}(N_t)\subseteq \mathrm{MF}(N_{t+1})$ in CI; deltas receipted.
  \item \textbf{VO-KKT-RESID:} Convex class declared; residuals and dual gap $\le$ tolerances.
  \item \textbf{VO-CONS-BAL:} Conservation: observed $\Delta V$ matches declared spend within tolerance.
  \item \textbf{VO-PR/ISS-CACHE:} L2 certificates only accepted from non--revoked cache entries.
\end{itemize}

\section{Operational Checklists (Pseudo-Code)}
\begin{auditbox}
\textbf{Proof Surface (Header--Only)}
\begin{verbatim}
Input: headers H = {h_1, ..., h_n} (canonical bytes)
1. Sort H lexicographically (byte-wise)
2. Compute leaf hashes L_i = H(h_i)
3. Build binary Merkle tree over {L_i}
4. Output root R
\end{verbatim}
\end{auditbox}

\begin{auditbox}
\textbf{Selective Disclosure Verification}
\begin{verbatim}
Input: header h (payload_root ρ), revealed fields F*, inclusion proofs π*
For each (field, value, proof) in (F*, π*):
  a) verify Merkle path to ρ
If all paths verify, accept fields as authentic w.r.t. ρ
\end{verbatim}
\end{auditbox}

\begin{auditbox}
\textbf{Level-1 DRO/KKT Receipt}
\begin{verbatim}
Input: transcript T, convex class C, residuals (r_stat, r_pri, r_dual), duality gap g, tolerances τ*
Require: C ∈ {QP, SOCP, SDP}
Check: r_stat ≤ τ_stat AND r_pri ≤ τ_pri AND r_dual ≤ τ_dual AND g ≤ τ_gap
\end{verbatim}
\end{auditbox}

\section{Assumptions and Limitations}
\begin{itemize}
  \item \textbf{Collision resistance:} Security reduces to assumptions on $H$ and EdDSA; no bespoke crypto.
  \item \textbf{Determinism scope:} Fixed toolchain and deterministic encodings are required; exact cross--ISA floating point may require fixed--point or constrained kernels.
  \item \textbf{STL monitoring:} Dense--time properties via bounded monitors and robust--satisfaction intervals (sound but conservative).
  \item \textbf{Level--2 costs:} PR/ISS accepted via audited cache with revocation; full online recomputation is out of scope for high--rate loops.
\end{itemize}

\section{Context and Prior Art (Neutral)}
This program synthesizes reproducible supply--chain attestations (deterministic builds; byte--identical artifacts), transparent logs with tamper--evident commitments (hash--chained receipts; Merkle proof surfaces), and formal control/verification for runtime safety (STL/SMT gating; CLF/CBF; KKT/PR/ISS receipts). The contribution is a normalized architecture in which every consequential step emits a typed, auditable, selectively disclosable receipt, allowing independent conformance checks and reproducible replays.

\section{Conclusion}
We provide a neutral, safety--first architecture for verifiable computation with compositional receipts, deterministic encodings, formal norms and governance, DRO control with explicit certificates, and privacy by selective disclosure. Short lemmas, obligations, and pseudo--code make the program practically auditable.
